# Common comparison protocol — BM@N FHCAL three central muon scenarios

1. Same real NPZ (impact modules 8, 16, 19), all μ+ with PDG = −13, and the same recorded momenta. Check module identification/beam angles against experiment metadata.
2. Same spatial crop `EnergyDeposit[:, :, 2:7, :7]`, CNN/per-event representation `(N,7,7,5)`. There are 34 physical modules plus one beam hole, each with seven sections. Keep 8–10 absent by construction; **no 10-layer tensor** in the central models.
3. Same per-module random seed 42, stratified 80% train / 10% validation / 10% held-out test. In the pilot select 600 total events per module **before** splitting. No test-event fitting, normalization, model selection or threshold tuning.
4. Model A: one conditional CNN FM to direct central-section energy. Model B: one conditional MLP FM to original FHCal_GMM K=4 mixture parameters plus independently learned total central energy; both generate actual final 7×5×7 response maps. Model B uses the upstream physical projector and packet decoder (K=4, default 128 packets/component), adapted to central geometry.
5. For the pilot use 100 epochs, 20-step Euler and the **same held-out events** for evaluation. Each model checkpoint is selected by its own validation FM loss. Keep optimizer configurations and full metadata. Parameter-space CFM and direct voxel-space CFM losses have different numeric scales and must not be directly compared.
6. Measure per-module (8/16/19) and pooled: total-energy distribution, KS statistic, JS divergence, p-value (with zero-point-mass caveat), q99, per-layer spectra, longitudinal profile, occupancy (strict E>0), average transverse map and samples/sec. For method B report both smooth and packet decoder as separate ablations if feasible.
7. Evaluate model B's representation ceiling with original fitted codes on holdout **only in a separately labeled diagnostic**; do not train on or tune using this diagnostic. The primary benchmark should not rely on upstream's potentially overlapping sample bank.
8. Record CPU/GPU type, Slurm partition, code commit, upstream FHCal_GMM commit, each NPZ SHA256, exact checkpoint epoch, number of fitted training codes, fit CPU time, training time and generation time. End-to-end speedup vs Geant4 requires measured Geant4 baseline on the same task.
9. This pilot is not sufficient to conclude which architecture is better on the full sample; after smoke success run a matched larger dataset and multiple random seeds.
