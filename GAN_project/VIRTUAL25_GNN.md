# FHCal: виртуальная сетка 2,5 см → GNN

Активный `run_pipeline.py` запускает conditional WGAN-GP:

`N(0,I)[B,64] + c → CNN → Softplus [B,10,H,W] → O_ij → [B,54,10] → GNN → [B]`.

`H,W` вычисляются из физических границ. Выход CNN — плотность энергии;
`O_ij` — площадь пересечения в см². Сумма `O_ij * rho_jl` даёт физическую
энергию модуля/слоя. REAL не дробится на виртуальные ячейки и не логарифмируется
перед обучением. `log1p(E)` — только дополнительный признак критика.
Маски исключают пустые области и отсутствующие слои. Граф двунаправленный,
рёбра связывают модули с общей границей, включая переход 15→20 см;
признаки ребра — dx, dy, расстояние и длина общей границы.
GNN: четыре residual message-passing блока, LayerNorm, mean/sum pooling,
MLP без sigmoid. Не требует torch_geometric.

## Данные, которые необходимо проверить для конкретного запуска

В репозитории нет подтверждённой ROOT-геометрии и точного соответствия
старых индексов NPZ реальным ID. Код намеренно не подставляет их по догадке.
Нужны два JSON-файла (пути передаются явно):

1. `geometry.json`: `{"modules": [{"module_id": 1, "x": ..., "y": ...,
   "z": ..., "width": 15, "height": 15, "layers": 10}, ...]}`.
   Все координаты/размеры в см; 54 уникальных реальных ID, 34 малых и 20
   больших модулей. Число слоёв 1..10 берётся из проверенного `fSectVec`,
   а не автоматически из размера модуля. Порядок сортируется по ID.
   Показанный фрагмент — описание формата, не готовая геометрия.
2. `module_map.json`: объект `{"<real ID>": [row, col], ...}` для **той
   функции**, которой создан конкретный NPZ `[N,7,9,10]`. Проверяются
   уникальность, покрытие ID, нули вне карты и сохранение энергии каждого
   события. Неверную перестановку двух ID с сохранением суммы невозможно
   выявить одной проверкой энергии: сверяйте карту с кодом подготовки NPZ.

Альтернатива старому формату: `EnergyDeposit[N,54,10]` плюс `ModuleIds[54]`
в NPZ. В обоих форматах нужны `ParticlePoint[N,3]`,
`ParticleMomentum[N,3]`, `ParticlePDG[N]`. Ненулевые отсутствующие слои,
отрицательная/нечисловая энергия вызывают ошибку. Единицы энергии остаются
исходными: одинаковыми для train, validation и inference.

`pipeline.fhcal_data.geometry_from_root` умеет читать реальные ID и центры
через optional `uproot`; имя дерева и префикс split-веток задаются явно.
Размеры и проверенные числа слоёв передаются в `module_metadata`; автоматическое
угадывание вложенной схемы `fSectVec` не реализовано. `fZ` не считается передней
плоскостью. Для сохранения JSON используйте `dataclasses.asdict` для модулей.

## Запуск

Из `GAN_project` в отдельном Python-окружении:

```sh
pip install -r requirements-virtual25.txt
python run_pipeline.py --data /path/events.npz --geometry /path/geometry.json \
  --module-map /path/module_map.json --device cuda --output experiments/virtual25_gnn
# Продолжить до суммарных 200 эпох:
python run_pipeline.py --data /path/events.npz --geometry /path/geometry.json \
  --module-map /path/module_map.json --device cuda --output experiments/virtual25_gnn \
  --epochs 200 --resume
python -m unittest discover -s tests -v
```

Для нового формата NPZ `--module-map` не нужен. По умолчанию: CPU, 100 эпох,
батч 64, n_critic=5, lambda_GP=10, Adam lr=1e-4, betas=(0,0.9).
GP вычисляется по физическим энергиям с исключением отсутствующих слоёв.
Один шаг генератора каждые пять батчей критика, счётчик переносится между эпохами.

`c` содержит стандартизованные `(x0,y0,z0,px,py,pz)` и one-hot PDG.
Статистики/словарь вычисляются только на train и сохраняются в чекпойнте.
Неизвестный на train PDG вызывает ошибку. ParticlePoint — вершина генерации,
не точка входа; старая потеря, связывавшая её с центром ливня, не переносится.
Детерминированный train/validation split 90/10, без урезания validation.

`checkpoint.pt` сохраняется атомарно после каждой эпохи: обе модели,
оптимизаторы, RNG, split, статистики условий и геометрия. Resume проверяет
геометрию, SHA256 данных, карту и параметры разбиения/шагов. Загружайте только
доверенные чекпойнты. Для inference восстановите геометрию из
`signature.geometry`, ConditionEncoder из `conditions`, генератор с размером
`6 + len(pdg_codes)` и его state_dict. Подавайте стандартный нормальный шум
и условия через сохранённый encoder; результат уже в физических энергиях.

`metrics.jsonl` содержит потери, KS/W1/гистограммный JS суммарной энергии и
каждого модуля (также отдельно положительной части; пустая часть → null),
строгие/почти нулевые доли (порог 1e-6 в исходных единицах), ошибку продольного
профиля, центр/радиус ливня, долю энергии малых модулей и соседние корреляции.
ID 8/16/19 не являются индексами: метрики именуются по реальным ID.
Также выводятся распределения полной энергии по PDG и группам x0/y0
относительно train-медианы. KS — статистика без p-value; JS зависит от бинов.

## Проверки и ограничения

Тесты используют синтетическую геометрию и проверяют точные площади (225/400
см²), частичные пересечения, маски, рёбра, сохранение энергии, ошибки карты,
обратный градиент через CNN/агрегацию/GNN/GP и обучение с resume, совпадающее
с непрерывным CPU-запуском. Полноценное обучение на Geant4 здесь не выполнялось.
Точное соответствие ROOT/NPZ и разнообразие попаданий во все модули требуют
проверки на реальных данных. По умолчанию рёбра только через общие границы;
разрывы в реальной геометрии могут давать изолированные вершины.

Softplus не воспроизводит строгие нули активных модулей автоматически:
следите за метриками разреженности. Виртуальная карта — внутреннее представление,
её детализация внутри модуля не определяется однозначно наблюдаемой энергией.
Старые CNN и старый trainer сохранены для истории, но новый entrypoint не
использует их метрики/нормализацию/логгеры, рассчитанные на `[B,L,7,9]`.
